# قدم ۳ — راه‌اندازی بک‌اند پایتونی روی localhost (حالت زنده و قابل‌ادیت)

## ۳.۱ ساخت محیط مجازی (venv) و نصب پکیج‌ها
همیشه تو پروژه‌های پایتون یه محیط مجازی جدا می‌سازیم، تا پکیج‌های این پروژه با بقیه‌ی سیستم قاطی نشن:
```bash
cd ~/service-desk-hub/backend_py
python3 -m venv venv
source venv/bin/activate
```
بعد از این دستور، اول خط ترمینال باید `(venv)` رو ببینین — یعنی محیط مجازی فعاله. حالا پکیج‌ها رو نصب کنین:
```bash
pip install -r requirements.txt
```

> ⚠️ هر بار که ترمینال جدید باز می‌کنین و می‌خواین سراغ این پروژه برین، اول باید دوباره `source venv/bin/activate` رو بزنین.

## ۳.۲ ساخت فایل .env
```bash
cp .env.example .env
nano .env
```
داخلش این خط‌ها رو با مقادیر واقعی خودتون پر کنین:
```
DATABASE_URL=postgresql://sdhub_user:همون‌رمزی‌که‌ساختین@localhost:5432/sdhub
JWT_SECRET=یه رشته‌ی طولانی و رندوم (دستور زیر رو بزنین بسازتش)
```
برای ساختن یه `JWT_SECRET` امن:
```bash
openssl rand -base64 48
```
خروجیش رو کپی و جای `JWT_SECRET` تو `.env` بذارین. فایل رو ذخیره کنین (تو nano: Ctrl+O بعد Enter بعد Ctrl+X).

## ۳.۳ ساخت اولین کاربر ادمین
```bash
python scripts/create_admin.py admin "مدیر سیستم" "یک-رمز-قوی-اینجا"
```
اگه با موفقیت انجام شد، پیام `Admin user "admin" is ready.` رو می‌بینین.

## ۳.۴ بالا آوردن سرور در حالت زنده (auto-reload)
```bash
uvicorn main:app --reload --port 4000
```
باید این‌جور چیزی ببینین:
```
Uvicorn running on http://127.0.0.1:4000
Application startup complete.
```
پرچم `--reload` یعنی هر بار فایلی رو تو پروژه عوض کنین (چون Python هستین، خیلی زود باهاش کار می‌کنین)، سرور خودش ری‌استارت می‌شه.

## ۳.۵ تست سریع که زنده‌ست
تو یه ترمینال دیگه (یا از همون VM با مرورگر):
```bash
curl http://localhost:4000/api/health
```
باید ببینین: `{"ok":true}`

## ۳.۶ مستندات خودکار API (این یکی مخصوص FastAPI‌ه و رایگان میاد!)
این آدرس رو تو مرورگر باز کنین:
```
http://localhost:4000/docs
```
یه صفحه‌ی تعاملی (Swagger UI) می‌بینین که تمام endpoint هایی که ساختیم رو لیست می‌کنه — می‌تونین مستقیم از همون صفحه لاگین کنین و هر endpoint رو تست کنین، بدون نوشتن حتی یه خط کد یا curl. برای یادگیری FastAPI خیلی خوبه که ببینین هر route چه شکلی از داده می‌خواد.

## ۳.۷ خود داشبورد (همه‌ی گزارش‌ها + راستر شیفت)
این آدرس رو باز کنین — کل مجموعه‌ی داشبورد (نمای کلی، SDCM، AICC، SLA، و راستر شیفت) همین‌جا سرو می‌شه:
```
http://localhost:4000/dashboard/
```
این دقیقاً همون فایل‌های HTML مستقلیه که قبلاً باهم ساختیم، فقط الان به‌جای باز کردن مستقیم فایل (`file://`)، از طریق همین سرور پایتونی سرو می‌شن. فعلاً راستر شیفت هنوز از `localStorage` مرورگر استفاده می‌کنه (طبق نقشه‌ی `docs/04`، وصل کردنش به همین API قدم بعدیه).

## ۳.۸ صفحه‌ی تست ساده (اختیاری، برای اطمینان از سلامت API)
این آدرس رو هم امتحان کنین:
```
http://localhost:4000/admin
```
یه صفحه‌ی خیلی ساده که می‌تونین باهاش:
1. با یوزر/پسورد ادمینی که ساختین لاگین کنین
2. ستون‌های راستر رو مستقیم از دیتابیس واقعی بخونین
3. یه عضو تیم جدید اضافه کنین و ببینین تو دیتابیس ذخیره می‌شه

اگه این سه‌تا کار کردن، یعنی **کل زنجیره** (مرورگر → API → دیتابیس) زنده و سالمه. ✅

## ۳.۹ اگه از سیستم خودتون (نه از داخل VM) می‌خواین ببینین
اگه VM رو با VirtualBox/VMware/Hyper-V بالا آوردین و می‌خواین از مرورگر ویندوز/مک خودتون بهش وصل شین، باید پورت ۴۰۰۰ رو forward کنین:
- **VirtualBox:** Settings → Network → Advanced → Port Forwarding → یه قانون جدید: Host Port `4000` → Guest Port `4000`
- بعدش تو مرورگر خودتون همون `http://localhost:4000/dashboard/`، `http://localhost:4000/admin` یا `http://localhost:4000/docs` رو باز کنین — انگار مستقیم رو سیستم خودتونه.
