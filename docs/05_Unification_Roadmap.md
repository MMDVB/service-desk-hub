# نقشه‌ی راه — یکپارچه‌سازی کامل داشبوردها

هدف نهایی: یه اپلیکیشن واحد و تمیز (نه ۵ فایل HTML جدا) که همه‌ی گزارش‌ها + راستر رو با ظاهر یکدست و دیتابیس مشترک پوشش بده و قابل توسعه باشه.

برای رسیدن به این هدف بدون گیر کردن وسط راه، ۴ فاز جدا تعریف کردم. هر فاز کامل و قابل‌استفاده‌ست — یعنی اگه یه‌جایی متوقف شدیم، چیزی که تا اون‌جا ساختیم خراب/نصفه نمی‌مونه.

---

## فاز ۱ — پایه‌ی دیتابیس برای تاریخچه‌ی گزارش‌ها ✅ (انجام شد و تست شد)
جدول‌های `sdcm_reports` / `aicc_reports` / `sla_reports` به دیتابیس اضافه شدن + یه API کامل (`/api/reports/...`) براشون ساخته شد. تست کامل انجام شد: ذخیره‌ی خلاصه‌ی روزانه، جایگزین‌شدن خودکار اگه همون تاریخ دوباره آپلود بشه (upsert)، گرفتن تاریخچه‌ی یه بازه، و گرفتن یه روز خاص — همه با دیتابیس واقعی تست شدن، نه فقط نوشته شدن.

**Endpoint های جدید:**
```
POST /api/reports/{sdcm|aicc|sla}          { date, summary }   → ذخیره/آپدیت خلاصه‌ی یه روز
GET  /api/reports/{sdcm|aicc|sla}?from=&to= → تاریخچه‌ی یه بازه
GET  /api/reports/{sdcm|aicc|sla}/{date}    → خلاصه‌ی یه روز خاص
```
هر سه گزارش از یه ساختار مشترک استفاده می‌کنن (فیلد `summary` به‌صورت JSON آزاد) — چون شکل دقیق خلاصه‌ی هرکدوم فرق داره (SDCM نرخ ثبت، AICC نرخ پاسخ‌گویی، SLA توزیع اولویت) ولی نیازی نیست برای هرکدوم جدول جدا طراحی کنیم.

**چیزی که هنوز نیست:** خود صفحات SDCM/AICC/SLA هنوز به این API وصل نیستن — الان فقط زیرساخت آماده‌ست. فاز ۳ دقیقاً همینو انجام می‌ده.

## فاز ۲ — سیستم طراحی مشترک (Design System)
یه فایل CSS واحد (رنگ‌ها، فونت، دکمه‌ها، هدر/سایدبار) که هر ۵ صفحه ازش استفاده کنن. نتیجه: ظاهر کاملاً یکدست، بدون اینکه منطق داخلی هیچ گزارشی دست بخوره. کم‌ریسک‌ترین قدم برای حس «یه سیستم واحد».

## فاز ۳ — وصل کردن گزارش‌ها به API
هر سه گزارش (SDCM/AICC/SLA) به‌جای اینکه فقط تو مرورگر بمونن، بعد از پردازش فایل اکسل، نتیجه رو به بک‌اند پایتونی می‌فرستن تا ذخیره بشه. راستر هم که از قبل تو نقشه بود (`docs/04`) دقیقاً همین مسیر رو طی می‌کنه.

## فاز ۴ — اپلیکیشن یکپارچه‌ی واقعی (SPA)
وقتی فاز ۱ تا ۳ جواب داد و مطمئن شدیم داده‌ها/منطق درست کار می‌کنن، اون‌موقع می‌ریم سراغ بازنویسی همه‌چیز به‌صورت یه اپلیکیشن واحد (React یا مشابه) با یه سایدبار واقعی، یه صفحه، بدون رفت‌وآمد بین فایل‌های جدا. این فاز طولانی‌ترینه (چند هفته کار)، برای همین آخر می‌ذاریمش — روی پایه‌ای که قبلاً تست شده ساخته می‌شه، نه از صفر و با ریسک بالا.
